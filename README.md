# TARM — Tiny Amnezia Routing Manager

Небольшой клиент AmneziaWG для OpenWrt с маршрутизацией по доменам, IP-адресам и подсетям. Конфигурация туннеля и списки живут в одном приложении; отдельный DNS-прокси не нужен. Для маршрутов используются `dnsmasq-full`, nftables и таблица policy routing. Есть CLI и страница LuCI.

Проект пока в версии 0.6.0. Он рассчитан в первую очередь на устройства вроде Xiaomi Mi Router 4C (MT7628, 16 МБ flash, 64 МБ RAM). На физическом Xiaomi Mi Router 4C проверены комплекты для OpenWrt 25.12.5 и 24.10.8: установка, туннель AmneziaWG и маршрутизация из LAN. После установки на 24.10.8 в overlay осталось 7,1 МиБ.

## Как это работает

`dnsmasq-full` кладёт адреса выбранных доменов в nft set. Пакеты с LAN к этим адресам получают метку `0x700000` и идут через `awg0` по таблице 700. В таблице есть защитный маршрут blackhole, а правило для помеченного трафика сохраняется при обычном `apply`. Nft-правила и статические наборы обновляются одной транзакцией; динамические DNS-наборы при этом сохраняются. Соединения сохраняют метку в conntrack. Внешние UDP-пакеты туннеля получают отдельную метку `socket_mark`, чтобы обходить правило для LAN.

В LuCI создаются именованные списки. В одном списке можно смешивать домены, IPv4, IPv6 и подсети CIDR: тип записи определяется автоматически. Домены обрабатываются через `dnsmasq`, адреса и подсети — сразу через nftables. Можно подключить HTTPS-подписку или совместить её с ручными записями. Список целиком включается для VPN либо прямого подключения. Прямые списки имеют приоритет при совпадении IP-адресов. Подписки обновляются ежедневно и по кнопке; размер загружаемого файла ограничивается во время загрузки. Если загрузка не удалась, остаётся предыдущая версия файла.

Если в настройках задан IP DNS-сервера VPN, выбранные домены разрешаются через него; запросы к этому адресу тоже направляются в туннель. Без этой настройки запросы идут через обычные upstream-серверы `dnsmasq`.

## Установка

Нужны `tarm`, `luci-app-tarm`, `amneziawg-tools` и патченный `kmod-amneziawg`. Ядро должно точно совпадать с зависимостью `kernel` у kmod: чужой kmod на OpenWrt не загрузится. Для собственной сборки прошивки собирайте kmod из того же дерева и с тем же kernel ABI.

Комплект для официальной OpenWrt 24.10.8 на `ramips/mt76x8` лежит в `dist/openwrt-24.10.8-ramips-mt76x8/` (`.ipk`, `opkg`). Для официальной OpenWrt 25.12.5 на том же target комплект лежит в `dist/openwrt-25.12.5-ramips-mt76x8/` (`.apk`, `apk`). В обоих случаях проверяйте полное значение зависимости `kernel` у kmod, а не только номер релиза OpenWrt. Сборка собственного образа с другим kernel ABI требует отдельного kmod.

Проверьте свободное место перед установкой зависимостей. После проверки ABI скопируйте на роутер соответствующий комплект и установите все четыре локальных пакета. Для 25.12.5:

```sh
df -h /overlay
apk update
apk add --allow-untrusted /tmp/kmod-amneziawg-6.12.94.3.1.20260812-r3.apk /tmp/amneziawg-tools-3.1.20260812-r1.apk /tmp/tarm-0.6.0-r8.apk /tmp/luci-app-tarm-0.6.0-r10.apk
```

Для 24.10.8 замените штатный `dnsmasq` на `dnsmasq-full` при установке пакетов. На чистом образе эти пакеты конфликтуют из-за общих файлов:

```sh
opkg update
opkg remove dnsmasq
opkg install /tmp/kmod-amneziawg_*.ipk /tmp/amneziawg-tools_*.ipk /tmp/tarm_*.ipk /tmp/luci-app-tarm_*.ipk
```

Автоматического установщика пока нет. Перед установкой вручную проверьте ABI ядра и выберите комплект для своей прошивки.

На уже настроенном `awg-route` сначала скопируйте `/etc/config/awg-route` в `/etc/config/tarm` и каталог `/etc/awg-route` в `/etc/tarm`; пути к собственным файлам списков в новом конфиге тоже замените на `/etc/tarm/`. Установите новые пакеты, проверьте `tarm check whatsapp.com` и `tarm apply`, затем удалите старые пакеты командой `apk del --no-scripts --no-commit-hooks luci-app-awg-route awg-route`. Уберите старые записи cron и файлы `awg-route.nft` и `awg-route.conf`, после чего повторите `tarm apply`. Прежние конфиги можно оставить как резервную копию. На тестовом 4C настройки, туннель и локальные списки перенесены именно так. Сетевые правила nftables по-прежнему хранятся во внутренней таблице `awg_route`: при смене имени пакета она не теряет накопленные DNS-адреса.

Пакеты самого приложения занимают считанные килобайты. Главный расход места приходится на `dnsmasq-full`, `ip-full`, nftables и AmneziaWG с зависимостями. На виртуальной OpenWrt 25.12.5 размеры установленных основных пакетов были около 414, 504, 781, 81 и 114 КиБ соответственно; дополнительные библиотеки и kmod тоже займут место. Поэтому 9 МБ свободного overlay выглядят достаточными для пробной установки, но итог зависит от уже установленных пакетов на вашем образе.

После установки откройте **Службы → TARM**. Вставьте обычный текстовый конфиг AmneziaWG с `[Interface]`, `[Peer]` и `Address`. В блоке **Routing lists** создайте список, добавьте в него домены, IP-адреса или подсети, выберите **VPN** и включите список. Потом включите маршрутизацию и нажмите **Save & Apply**. Для исключений создайте отдельный список с маршрутом **Direct**. Приложение понимает параметры маскировки `Jc`, `Jmin`, `Jmax`, `S1`–`S4`, `H1`–`H4` и другие поля, которые принимает установленная версия `awg`. Скриптовые хуки `PreUp`, `PostUp`, `PreDown`, `PostDown` не исполняются.

В блоке **Built-in VPN lists** находятся 18 готовых групп из предоставленного пользователем экспорта `.mtrickle` от 10 октября 2026 года. Каждая включается своей галочкой и направляется через VPN. Группы лежат в пакете локально и не скачиваются; при установке все выключены, чтобы роутер с 64 МБ RAM не загружал тысячи правил без необходимости. Включённые правила внутри каждой группы сохранены. Подсети с пересечениями объединены без изменения охвата. Четыре правила в виде одиночного слова (`youtube`, `imdb`, `intel`, `playstation`) пропущены: TARM умеет домены с точкой, IP-адреса и CIDR, а соответствующие домены `.com` в экспорте уже есть. Для повторной подготовки файлов служит `tools/build-mtrickle-presets.py`.

Кнопка **Import a list** открывает окно, в котором можно найти готовый список из [v2fly/domain-list-community](https://github.com/v2fly/domain-list-community), например `telegram`, и кнопкой **Add VPN list** создать и скачать его. Для Telegram к доменам добавляется снимок [официальных IP-подсетей](https://core.telegram.org/resources/cidr.txt): приложение Telegram может подключаться к дата-центрам напрямую по IP. Для `whatsapp` добавляется снимок 108 подсетей группы Meta из пользовательского экспорта `.mtrickle` от 10 октября 2026 года. Он покрывает прямые подключения WhatsApp по IP, но также направляет через VPN другие сервисы Meta в этих подсетях. Снимок не обновляется вместе с доменным каталогом. Для своего списка можно вставить много доменов, IP-адресов и подсетей сразу или выбрать локальный `.txt`: сначала создайте и сохраните именованный список выше, затем выберите его в импортере. Импорт умеет добавлять к уже загруженным записям или заменять их. Лимит одного загружаемого файла — 256 КиБ, итогового списка — 1 МиБ.

Для одной тематики выбирайте один источник: встроенную галочку или онлайн-каталог. Одинаковые записи TARM объединяет при применении, но повторная загрузка списка не даёт пользы. Онлайн-каталог остаётся для дополнительных и обновляемых списков.

При импорте каталога раскрываются вложенные `include:`. Правила `full:`, `keyword:` и `regexp:` пропускаются, потому что текущая маршрутизация понимает только домен вместе с поддоменами; одиночные имена без точки тоже пропускаются. Поэтому импортированный список может отличаться от оригинального geosite. Для каталога действует лимит 128 вложенных файлов и 2 МиБ суммарной загрузки.

CLI для быстрой проверки:

```sh
tarm import /tmp/client.conf
uci set tarm.main.enabled=1
uci set tarm.streaming=list
uci set tarm.streaming.enabled=1
uci set tarm.streaming.route=vpn
uci add_list tarm.streaming.domain='example.org'
uci add_list tarm.streaming.domain='203.0.113.7'
uci add_list tarm.streaming.domain='2001:db8::/32'
uci commit tarm
tarm apply
tarm check www.example.org
tarm status
tarm catalog-add telegram
cp /tmp/domains.txt /etc/tarm/import.txt
tarm import-list streaming append
```

Подписка в `/etc/config/tarm`:

```text
config list 'streaming'
    option enabled '1'
    option route 'vpn'
    list domain 'example.org'
    list domain 'video.example.net'
    list domain '203.0.113.7'
    list domain '2001:db8::/32'
    option url 'https://example.org/domains.txt'
```

Подписка необязательна. Её формат: один домен, адрес или подсеть на строку, `#` для комментариев. Допускается начальная точка. Старые поля `vpn_domain`, `direct_domain`, `vpn_file` и `direct_file` в секции `main` пока поддерживаются для совместимости с прежними настройками, но в LuCI новые записи добавляются в именованные списки.

## Проверка и ограничения

В QEMU проверены установка пакета, запуск после перезагрузки, подписки и исключения, наполнение nft set через DNS, маршруты при поднятом и упавшем интерфейсе. Две виртуальные OpenWrt 25.12.5 с AWG 3.1 установили рукопожатие и передали ICMP через туннель, в том числе с параметрами маскировки. На физическом Xiaomi 4C с OpenWrt 25.12.5 проверены сохранение настроек через LuCI, сообщение об ошибке при неверном конфиге и работа туннеля. После прошивки 24.10.8 проверены рукопожатие, ICMP через `awg0`, HTTP 200 от `telegram.org` из LAN с ростом счётчиков AWG и запуск туннеля после перезагрузки. Точка доступа Wi-Fi восстановлена из резервной копии и поднялась; подключение отдельного Wi-Fi-клиента на 24.10.8 не проверялось.

Доменные правила основаны на ответах DNS. Если клиент использует собственный DoH/DoT или уже знает IP-адрес, доменное правило не сработает; явное правило для IP-адреса или подсети работает без DNS. Общие IP CDN могут затронуть несколько доменов сразу. В отличие от MagiTrickle, здесь нет отдельного DNS-прокси, учёта TTL каждого ответа и анализа цепочек CNAME: адреса, полученные из DNS, живут в nft set не более часа; заданные вручную IP-адреса и подсети остаются до смены списка. При смене списков активные соединения могут сохранять старую метку до закрытия, а сохранённые DNS-адреса — прежнюю политику до истечения таймаута. Таблица 700 настраивается в UCI; приоритеты правил 16999 и 17000 пока фиксированы. При изменении метки, номера таблицы или VPN DNS-сервера сначала выполните `tarm stop`, затем `tarm apply`.

Идея списков взята из [MagiTrickle](https://github.com/MagiTrickle/MagiTrickle). Для туннеля используется [AmneziaWG](https://github.com/amnezia-vpn/amneziawg-linux-kernel-module).

Код TARM распространяется по MIT. Патч в `kmod-amneziawg/patches/` относится к модулю AmneziaWG и распространяется по GPL-2.0, как и [исходный модуль](https://github.com/amnezia-vpn/amneziawg-linux-kernel-module).
